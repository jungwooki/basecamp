# 축구레슨센터 선수 관리 대시보드 · 구현 제안 v1.0

## 범위와 상태

사용자 확정: 축구레슨장이 MPS 인증센터로 참여하고, 인근 한의원 측정센터에서 측정한 결과를 받아 선수를 맞춤 관리한다. MPS는 레슨센터에 대시보드를 제공하며 레슨센터는 프로그램·대시보드 월 구독료를 낸다. 측정비는 A/B 두 결제안을 준비한다.

`dashboard.html`은 가상 선수 8명을 보여주는 화면 제안용 데모다. 선수단(U12/U11) 전환, 요약·피지컬·성장·멘탈·코치 관리 탭, 검색·상태 필터, 선수 관리 지도와 카드 선택이 동작한다. 실제 인증, 데이터베이스, 기관 연동, 결제, 저장, 자동 알림은 구현하지 않았다. 아래 범위도 정식 제공 약정이 아니라 구현 협의안이다.

## 역할 및 조회 범위 제안

| 역할 | 필요한 범위 | 변경 권한 |
| --- | --- | --- |
| 레슨센터 관리자 | 해당 센터 소속·공유 승인된 선수, 코치 배정·운영상태 | 코치·선수 배정, 센터 운영 기록 |
| 담당 코치 | 배정 선수 중 열람 허용된 결과와 관리 계획 | 코치 목표·관찰·점검 기록 |
| 측정센터 담당 | 해당 기관의 예약·측정·공유 기록 | 측정 결과·전문가 의견 작성 및 정정 이력 |
| MPS 운영 담당 | 서비스 운영에 필요한 범위 | 계정·기관 연결·지원 기록; 건강정보 전면 열람을 기본값으로 두지 않음 |

측정센터 결과 원본과 코치 관리 기록을 분리한다. 코치는 원본 측정 결과를 덮어쓰지 않는다. 다른 레슨센터 선수 조회를 차단하는 서버 측 권한 검증이 필요하다. 데모의 화면 차단은 실제 보안 구현을 의미하지 않는다.

## 선수별 기본 정보 구조 제안

- 관리 ID, 소속 센터, 반, 담당 코치, 등록·휴면·퇴소 상태.
- 측정 기관·예약일·측정일·결과 버전·결과 수신일.
- 공유 승인 상태·수신 기관/담당 범위·허용 항목·유효기간·철회일.
- 성장·멘탈·피지컬 중 공유 허용된 결과와 측정센터 전달사항.
- 코치 관리 목표·실행 기록·작성자·작성일·다음 관리 점검일.
- 측정 회차별 A/B 결제안·청구번호·결제상태. 결제는 결과 공유 동의와 별도 상태로 관리.

## 주요 업무 흐름

1. 센터 계약·계정 등록 → 관리 책임자·담당 코치 지정.
2. 선수 등록 시 소속과 필요한 정보 공유 절차 확인. 센터 대표자의 모집 신청 동의로 선수정보 공유를 대신하지 않음.
3. 한의원 측정센터 예약 → 측정 수행 → 결과 작성 → 공유 승인 범위 확인 → 대시보드 반영.
4. 코치가 결과·전달사항을 확인 → 선수 관리 목표 작성 → 점검기한 지정 → 실행·관찰 기록.
5. 추가 해석이 필요한 사항은 측정센터 문의. 업무 점검기한을 의학적 재검 시점으로 자동 치환하지 않음.
6. 퇴소·이적·동의 철회·코치 변경 시 소속, 과금 기준, 접근 권한을 각각 갱신.

## 상태·지표 정의

- 전체 관리 선수: 현재 센터 관리 대상 선수. 청구 선수 수와 같다고 가정하지 않음.
- 결과 대기: 측정 완료 후 결과가 아직 수신되지 않은 업무 상태.
- 공유 확인 필요: 승인 범위·수신자·절차 확인 전 결과 미표시.
- 점검기한 도래: 레슨센터가 정한 다음 관리 점검일 도래·경과. 건강 위험도 판정 아님.
- 관리 중: 결과 확인 후 코치의 관리 기록을 이어가는 상태.

## 월 구독과 측정비

- 월 구독: 레슨센터 → MPS. 요금 방식·금액·포함 인원·과금 선수 정의·집계일·중도 등록·퇴소·일할 계산 미정.
- A안: 선수·보호자 → 측정센터 개별 결제. 개인별 예약·결제·환불 기록.
- B안: 지정 일괄 결제자 → 측정센터 합산 결제. 일괄 결제자와 보호자 수납 담당을 계약에서 지정. 통합 청구번호와 선수별 배분표를 함께 관리.
- 중복 방지 키 제안: 선수 관리 ID + 측정 회차 ID. 한 회차의 한 선수에 하나의 결제안 적용.
- 결제금액·취소·환불·미수금은 업무 기록이며, 결제 성공을 결과 공유 승인으로 사용하지 않음.

## 실제 개발·Launch 전 확정 사항

계정 인증, 센터별 권한, 실제 결과 전달 API 또는 확인된 수동 절차, 동의·철회 처리, 변경·조회 기록, 암호화와 보관·종료 처리, 요금 산정 기준, 결제·환불 연결 주체, 알림 채널·담당자, 기능별 제공 일정. 건강정보의 전달 구조와 기관별 정보 처리 역할에 맞춰 필요한 문서를 별도로 확정한다.

## 디자인 반영 · 2026-09-26

[현재 MPS 팀 대시보드](https://sportsmps.com/team-dashboard)에 로그인하여 선수단 선택·요약·피지컬 화면을 확인하고 디자인을 반영했다. #191919 배경, 짙은 회색 라운드 카드, 큰 제목, 알약형 탭, 파랑·베이지·보라 영역 색상과 선수 선택 흐름을 참고했다.

실제 팀·선수 정보, 점수, 계정·인증정보는 예시 파일에 복사하지 않았다. 선수 8명 및 U12/U11 그룹은 가상 데이터다. 선수 관리 지도는 측정 후 경과일과 코치 관리기록 완료율을 표시하는 가상 업무 차트이며 원 서비스의 경기력·건강 점수 모델을 재현하지 않는다. 실제 측정값·의학적 소견은 표시하지 않는다.

모바일에서는 탭과 선수 표를 각각 가로로 스크롤할 수 있다. 탭은 좌우 방향키·Home·End로도 전환할 수 있다. 상단 요약·영역 카드는 선택 선수단 기준이며 아래 검색·상태 필터는 선수 목록에 적용한다.

## 가상 선수 유형 확장

6명의 사례 선수와 결과 대기·공유 확인 선수 2명, 총 8명입니다.
- 강도윤: 조기성장·피지컬 우세
- 서이준: 지연성장·기술 집중
- 문하람: 멘탈 하락
- 윤태오: 피지컬·멘탈 강점
- 정시온: 안정형
- 오유찬: 컨디션 반등형

이름·유형·점수·관리계획 모두 창작한 예시입니다.
7·8·9월 세 회차 점수는 0~100의 데모 전용 값이며 실제 MPS 척도나 진단 기준이 아닙니다.
증감은 8월 대비 9월 차이입니다. 피지컬 세부 항목과 종합점수는 각각 설정한 값이며 공식 계산식은 없습니다.
성장 유형은 사례 라벨로 미리 부여하며 점수로 자동 분류하지 않습니다.
`demo-personas.json`은 가상 데이터 명세 사본입니다. 오프라인 HTML은 `dashboard.js` 내 같은 데이터를 사용합니다.
수정 시 두 파일을 함께 갱신합니다. 대기·미승인 선수에는 유형·점수를 넣지 않습니다.
